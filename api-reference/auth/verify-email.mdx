---
title: "Verify an email address"
sidebarTitle: "Verify email"
description: "Mark a staff account's email address as verified from the emailed link."
api: "GET /email/verify/{id}/{hash}"
playground: "simple"
---

The verification email links here. Login is refused with `403 Email not verified` until this succeeds.
Accounts created from an invitation are already verified.

The link is **signed** and valid for **60 minutes**: call it exactly as it appears in the email,
including its `expires` and `signature` query parameters. A link that was changed, rebuilt by hand or
has expired answers `403 Invalid signature.`; ask for a new one with
[Resend the verification email](/api-reference/auth/resend-verification).

<ParamField path="id" type="integer" required>
  User id, from the link.
</ParamField>

<ParamField path="hash" type="string" required>
  Hash segment of the link, passed through unchanged.
</ParamField>

<ParamField query="expires" type="integer" required>
  Expiry timestamp, from the link.
</ParamField>

<ParamField query="signature" type="string" required>
  Signature, from the link.
</ParamField>

## Response

<ResponseField name="message" type="string" required>
  `Email verified.` or, when it was already done, `Already verified.`
</ResponseField>

<RequestExample>

```bash cURL
# Paste the whole link from the email, query string included.
curl "$VERIFICATION_LINK" \
  -H "Accept: application/json"
```

```javascript JavaScript
// verificationLink = the full URL from the email, query string included.
const res = await fetch(verificationLink, {
  headers: { Accept: "application/json" },
});
```

</RequestExample>

```json 200
{
  "message": "Email verified."
}
```

```json 200 (again)

```


</ResponseExample>
