## System

| Method | Path | Description |
| :-- | :-- | :-- |
| `GET` | [`/api/health`](/api-reference/system/health) | JSON health check for uptime monitoring (also at `/health`) |
| `GET` | [`/api/`](/api-reference/system/status-page) | HTML status page of the backend services |

## Share pages and sitemaps

These routes live **outside `/api`**, at `https://admin.theteam.com.tn`. They exist because the public site
is a static SPA: crawlers that don't run JavaScript would see an empty page, so the backend renders what
they need. (The site's training pages are also pre-rendered when the site is built: see
[Publishing and caching](/concepts/publishing-and-caching#pre-rendered-pages-on-the-public-site).)

| Method | URL | Description |
| :-- | :-- | :-- |
| `GET` | [`/share/blog/{slug}`](/api-reference/web/share-blog) | Open Graph page for a blog post, redirects people to the post |
| `GET` | [`/share/article/{slug}`](/api-reference/web/share-article) | Open Graph page for an article, in French or English |
| `GET` | [`/sitemap-trainings.xml`](/api-reference/web/sitemap-trainings) | Sitemap of published trainings |
| `GET` | [`/sitemap-articles.xml`](/api-reference/web/sitemap-articles) | Sitemap of published articles |

The site's `robots.txt` lists the two sitemaps **by their URL on this host**
(`https://admin.theteam.com.tn/sitemap-*.xml`). A sitemap may live on another host when the site's own
`robots.txt` points at it, so no proxy is configured on `theteam.com.tn`, where those paths answer `404`.

## Crawlers

`https://admin.theteam.com.tn/robots.txt` keeps this host out of search engines but lets them **fetch**
what the public site needs:

```text
User-agent: *
Allow: /share/
Allow: /api/
Allow: /storage/
Allow: /images/
Allow: /sitemap-trainings.xml
Allow: /sitemap-articles.xml
Disallow: /
```

| Path | Why crawlers may fetch it |
| :-- | :-- |
| `/share/` | Share pages: social networks read their preview tags. |
| `/api/` | The site renders its pages from the API. Search engines that run JavaScript (Googlebot) only call URLs that `robots.txt` allows, so without this line every API-driven page renders empty for them. |
| `/storage/`, `/images/` | Uploaded images and the training placeholder, used in pages, Open Graph tags and structured data. |
| `/sitemap-trainings.xml`, `/sitemap-articles.xml` | The site's live sitemaps, which its `robots.txt` references by this host's URL. |

Allowing a fetch is not allowing indexing: every response of this host carries
`X-Robots-Tag: noindex, nofollow, noarchive`, so API URLs never appear in search results. Two exceptions:
`/share/*` has no such header, and the sitemaps send a plain `noindex`, so the URLs they list are
followed.
