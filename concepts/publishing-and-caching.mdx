## Publish gating

Content is managed in the admin panel. The API serves an item only once it is published:

| Content | Visible when | Notes |
| :-- | :-- | :-- |
| Blog posts | `status = true` **and** `published_at` is set | A future `published_at` does **not** hide a post |
| Knowledge Corner articles | `status = true` **and** `published_at` is set **and reached** | A future date schedules the article: `404` until then |
| Trainings (list, options, sitemap) | `visibility_status = "published"` | See the note on training detail below |
| Testimonials | `is_pinned = true` (shown as **Published** in the admin) | Public submissions arrive unpublished |
| Webinars, FAQs | `is_published = true` | |
| Blog categories, article facets | Have at least one published post or article | |

<Warning>
  Two read endpoints are **not** gated:

  - [`GET /trainings/{idOrSlug}`](/api-reference/trainings/get) returns a training whatever its
    `visibility_status`. The payload includes `visibility_status`, so check it if you link to drafts.
  - [`GET /pages`](/api-reference/content/list-pages) and [`GET /pages/{slug}`](/api-reference/content/get-page)
    return unpublished pages. Filter with `?is_published=1` on the list.
</Warning>

Enrollment and devis submissions only accept **published** trainings, whatever the ids sent.

## Training catalogue cache

Training reads are cached for **5 minutes**:

- `GET /trainings` (per page, page size, search and pinned filter)
- `GET /trainings/{idOrSlug}`
- `GET /trainings/options`
- `GET /categories`
- `/sitemap-trainings.xml`

Each cache key includes the request language. Saving or deleting a training or a training category in
the admin panel **bumps a version number** that is part of every key, so the next request rebuilds the
payload. The 5-minute lifetime only matters for changes made outside the application, such as a direct
database edit.

<Tip>
  "The backend is right but the site is stale" is usually this cache, or the visitor's own browser cache,
  not a bug. Wait five minutes or save the training again in the admin panel. If only **search engines**
  see the old version, it is the pre-rendered page below: redeploy the site.
</Tip>

## Pre-rendered pages on the public site

When the site is built (`npm run build` in the frontend), it reads the published catalogue from this API
and writes one complete HTML page per URL:

| Site URL | Built from |
| :-- | :-- |
| `/trainings`, `/en/trainings` | [`GET /trainings`](/api-reference/trainings/list) (every page) and [`GET /categories`](/api-reference/trainings/categories), with `?lang=fr` / `?lang=en` |
| `/course/{slug}`, `/en/course/{slug}` | [`GET /trainings/{slug}`](/api-reference/trainings/get) for each published training, same languages |

Each page carries the training's own title, description, canonical URL, `hreflang` alternates, Open Graph
tags and `Course` / `ItemList` structured data, plus the full content, so crawlers read it without running
JavaScript. In the browser the site then refreshes the content from the API.

- **Pre-rendered pages are as fresh as the last site deploy.** A training published, renamed or
  unpublished in the admin panel shows up at once for visitors, but its pre-rendered page changes only
  when the site is deployed again. A training published since the last deploy is served as a normal app
  page until then.
- The build **fails** when it cannot read these endpoints, so keep them reachable from the machine that
  deploys, and keep their payload shapes stable: the build reads `id`, `slug`, `title`, `intro`,
  `overview`, `duration_label`, `price`, `certification`, `prerequisites`, `learning_objectives`,
  `quizzes_count`, `elearning_unlocked`, `modules`, `categories`, `featured_image_url`,
  `visibility_status` and `updated_at`.
- The site's training titles get a location suffix ("Formation PMP **en Tunisie**", "PMP Training
  **in Tunisia**") unless the title already names Tunisia.

Background and verification: [Training pages not visible on Google](/troubleshooting/trainings-not-indexed).

## Other caches

| Resource | Cache |
| :-- | :-- |
| `/sitemap-articles.xml` | 10 minutes, cleared on every article write |
| `/sitemap-trainings.xml` | 5 minutes (catalogue cache), sent with `Cache-Control: public, max-age=300` |
| Everything else | Not cached. Responses carry `Cache-Control: no-cache, private` |

## Images

Image fields are absolute URLs. Uploaded files are served from `https://admin.theteam.com.tn/storage/…`;
images inserted in rich text and some seeded content point to external hosts. Training images fall back
to `https://admin.theteam.com.tn/images/training-placeholder.jpg`, and articles without a cover return a
shared placeholder with `has_image: false`.

`/storage/` and `/images/` are allowed in this host's `robots.txt`, so search engines can fetch these
images for the site's pages, previews and structured data (see [Crawlers](/api-reference/system/overview#crawlers)).
